# 数据治理整改清单

## P0：真实交易前必须完成

- [x] P0-1：建立 Alembic 迁移基线，停止由应用启动过程修改表结构。
- [x] P0-2：订单冻结作品、版本、创作者、标题、价格、币种和许可快照。
- [x] P0-3：订单使用幂等键；同一买家同一商品只允许一个活跃订单；支付尝试独立留痕。
- [x] P0-4：退款不删除权益，改为撤销状态，并建立退款记录。

## P1：数据边界与可运营性

- [x] P1-1：拆分公开、个人和管理员作品接口，禁止公开读取草稿及驳回信息。
- [x] P1-2：明确 PostgreSQL 与 D1 边界，统一身份和迁移；需求数据不得成为匿名孤岛。
- [x] P1-3：建立事件定义、匿名身份、幂等去重及漏斗指标口径。
- [x] P1-4：补齐文件哈希、扫描状态、引用关系、软删除和孤儿清理。
- [x] P1-5：审核对象下沉到版本，允许已审核版本继续销售、新版本独立审核。
- [x] P1-6：增加复式账本、平台佣金、退款冲正和结算状态。

## P2：数据产品化与运维

- [x] 标记每个页面的数据来源：真实、半真实、演示（登记见数据字典）。
- [x] 用服务端 `/v1/marketplace` 数据替换首页及作品广场的核心作品数据。
- [x] 建立 PostgreSQL、上传文件的备份、隔离恢复流程和保留策略。
- [x] 建立数据字典、指标字典、数据保留和个人数据删除规则。
